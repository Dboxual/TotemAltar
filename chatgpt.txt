WHAT CHANGED IN 1.1.23

CHANGED — Shard kill progress now only counts when held in offhand
-------------------------------------------------------------------
Previous behaviour:
  AffinityListener checked the offhand first, but if no valid unmorphed shard was
  there, it fell through to scan the full hotbar (slots 0–8). A shard sitting
  anywhere in the hotbar silently accumulated kill progress without the player
  needing to put it in the offhand.

New behaviour:
  Only the offhand slot is checked. If the offhand does not contain a valid
  unmorphed Totem Shard, the kill event is ignored for all shard affinity types.
  No hotbar scan, no inventory scan, no main-hand fallback.

  All five affinity types (blast, shadow, storm, guardian, swap) are covered by
  the same path — there is one check, one slot, one rule.

  Morphed/typed shards continue to ignore kill events exactly as before
  (isMorphed() guard is unchanged).

Guide book updated:
  ItemUtil.createGuideBook() page 1: "Keep one in your hotbar" →
  "Hold one in your offhand" so the in-game text matches the new requirement.

WHAT CHANGED IN 1.1.22

REWORK — Bedrocker: countdown replaced with mining-feel behavior
----------------------------------------------------------------
Goal: the BedRocker should feel like a special pickaxe that actually mines
bedrock, not a magic ability that clicks once and waits.

Because bedrock has hardness -1, the client never shows crack animation and
the server never completes a natural break. The new implementation approximates
genuine mining using server-side block crack packets:

  1. Player holds left-click on bedrock with a BedRocker pickaxe.
     → BlockDamageEvent fires → mining session starts.

  2. Every 5 ticks (0.25 s), the server sends a sendBlockDamage progress update
     to the mining player. The crack visually grows from stage 0 to full over
     the configured break-seconds duration (default 5 s).

  3. If the player stops clicking or aims at a different block, the client sends
     BlockDamageAbort → BlockDamageAbortEvent fires → session is cancelled and
     the crack animation is reset on the client via sendBlockChange.

  4. As a belt-and-suspenders, the 5-tick loop also runs a raytrace gaze check
     (player.rayTraceBlocks(6.0)) and cancels if the player isn't looking at the
     exact original block. This catches any edge case where the abort event may
     not have fired.

  5. Session is also cancelled on PlayerQuitEvent and PlayerDeathEvent.

  6. If the player holds on-target for the full duration, the block is broken
     with the existing break effects (lightning, SMOKE particles, explosion sound)
     and the configured durability cost is applied.

Cancellation messages:
  "Mining stopped."              — player released click / looked away (abort event)
  "Mining interrupted — wrong tool."    — hotbarred a different item mid-mine
  "Mining interrupted — moved too far." — walked out of 7-block range
  "Mining interrupted — look at the block." — raytrace gaze check fallback

Config change — break-ticks → break-seconds:
  bedrock-relic.break-ticks (old, removed) → bedrock-relic.break-seconds (new)
  Default: 5 (seconds). All existing configs using break-ticks will fall back to
  the default (5 s) — update config.yml on the server to set a custom value.

FILES CHANGED
--------------
  BedrockBreakListener.java  — full rewrite: crack animation loop, BlockDamageAbortEvent,
                               PlayerDeathEvent, abortSession() with crack reset
  ConfigManager.java         — getBedrockBreakTicks() removed; getBedrockBreakSeconds() added
  config.yml                 — break-ticks: 100 → break-seconds: 5
  build.gradle.kts           — version 1.1.22
