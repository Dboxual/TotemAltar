WHAT CHANGED IN 1.1.25
================================================================================

CHANGED — Raised Bedrock Relic natural-spawn chances, cleaned up config naming
-----------------------------------------------------------------------------
This follows directly on from 1.1.24, which first added natural Bedrock Relic
generation to Ancient City, Nether Fortress, and Stronghold chests (on top of
the existing Bastion Remnant drop). The defaults from that release were
intentionally conservative; this release raises them and gives every
structure a clearly named, dedicated config key.

NEW DEFAULT CHANCES (all under bedrock-relic: in config.yml)
-----------------------------------------------------------------------------
  ancient-city-chance:     0.08  (8%)    per Ancient City chest   — was 0.02
  nether-fortress-chance:  0.06  (6%)    per Nether Fortress chest — was 0.02
  stronghold-chance:       0.05  (5%)    per Stronghold chest      — was 0.015
  bastion-chance:          0.05  (5%)    per Bastion Remnant chest — was 0.03
                                          (key renamed from "spawn-chance")

Each chance is independent — every structure rolls against its own value, so
raising one does not affect the others.

LOOT TABLES AFFECTED (vanilla minecraft: namespace, matched by key)
-----------------------------------------------------------------------------
  ancient-city-chance      -> chests/ancient_city, chests/ancient_city_ice_box
  nether-fortress-chance   -> chests/nether_bridge
  stronghold-chance        -> chests/stronghold_corridor,
                               chests/stronghold_crossing,
                               chests/stronghold_library
  bastion-chance           -> chests/bastion_bridge, chests/bastion_hoglin_stable,
                               chests/bastion_other, chests/bastion_treasure

No structure-generation hook is needed for any of these — BedrockRelicLootListener
hooks LootGenerateEvent, which fires the first time Minecraft populates a
container's contents (naturally generated or otherwise), and matches against
the loot table key shown above.

ITEM DROPPED — still the dormant relic, not the finished pickaxe
-----------------------------------------------------------------------------
Unchanged from 1.1.24: every drop is plugin.getItemUtil().createBedrockRelic() —
the dormant, NON-activated Bedrock Relic (Gilded Blackstone, "&6Bedrock Relic"
display name, "Dormant. Bring to a Bedrock block to awaken." lore), carrying
the BEDROCK_RELIC_KEY PersistentDataContainer tag (totemaltars:bedrock_relic)
that ItemUtil.isBedrockRelic() and the altar-binding flow check for. The
finished BedRocker pickaxe enchant is never placed directly in loot — it can
only be created by activating a relic on Bedrock, then binding the Activated
Bedrock Relic at a repaired Totem Altar.

BACKWARD COMPATIBILITY — old "spawn-chance" key still works
-----------------------------------------------------------------------------
The Bastion chance config key was renamed from "spawn-chance" to
"bastion-chance" for naming consistency with the other three structures.
ConfigManager.getBedrockRelicBastionChance() now checks for the old
"spawn-chance" key first:

  - If your config.yml already has "bedrock-relic.spawn-chance" set (from an
    earlier install), that value keeps being used for the Bastion chance —
    your customization is not silently overridden by the new default.
  - If "spawn-chance" is not present, "bedrock-relic.bastion-chance" is used.
  - New installs only ever see "bastion-chance" (the new default config.yml
    no longer ships "spawn-chance" at all).

Note: on first startup after upgrading, the plugin's normal copyDefaults
behaviour will add "bastion-chance: 0.05" into your existing config.yml
alongside your old "spawn-chance" line. That's expected and harmless — as
long as "spawn-chance" remains in the file, it keeps taking priority. Remove
it manually whenever you're ready to fully switch to "bastion-chance".
